## 1. Troca de usuário (uma sessão demo por vez)

- O cookie é único (`vyx_session`, `SameSite=Strict`, `routes_auth.py:79`). Fazer login de um demo **na mesma janela do
  admin substitui a sessão do admin**. Use **uma janela InPrivate/anônima separada** só para os demo, um usuário por
  vez: login → passos → logout. A janela do admin fica intacta.
- Limite: 20 logins por minuto por IP (`app.py:93`). CSRF exigido em POST/PUT/PATCH/DELETE (`app.py:218-224`). O login
  não exige CSRF; o logout exige.
- 1º login: a resposta traz `stage:"password_change"`. Qualquer rota de negócio responde 403 `stage` até trocar a senha
  (`app.py:225-226`).
- Nova senha (`auth/passwords.py:35-39`, `manifest.py:60`): pelo menos 10 caracteres, com maiúscula, minúscula e
  número, e diferente da atual. Trocar a senha encerra as outras sessões do usuário (`auth/service.py:530`).
- `demo.admin.inst`: se a política `mfa_required_for_admins` estiver ligada, o stage vira `mfa_enroll`
  (`auth/service.py:378-384`). Nesse caso, pule esse usuário (não cadastre TOTP sem decisão do proprietário).
- Senhas: nada em arquivo. Ficam só na memória do console (`PW`). Se a janela fechar, o admin redefine a senha:
  `POST /users/{id}/reset-password {"password":...}` (`routes_admin.py:125`), o que volta a exigir troca.

Ajudante para colar no console da janela InPrivate:

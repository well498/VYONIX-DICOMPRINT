## 2. Backup consistente ANTES e DEPOIS da homologação — A EXECUTAR

### 2.1 Mecanismo suportado
- O único backup automatizado do banco é o passo `backup.before_update` do `vyonix-deploy update`
  (steps/update.py:23-98). Executar uma atualização apenas para gerar backup **não é recomendado** (reinicia serviços,
  roda migração e faz parte do fluxo de atualização). Não há `vyonix-deploy backup`.
- Procedimento recomendado: **reproduzir manualmente o mesmo passo** (mesmo `pg_dump.exe` embarcado, mesmo usuário,
  mesmo formato `-Fc`, mesma estrutura de pasta e mesmo `backup.json`), para que o backup fique listado por
  `vyonix-deploy backups` e seja restaurável pelo `vyonix-deploy restore` oficial (RestoreBackupStep exige
  `backup.json` com `dump` e `sha256` em minúsculas e a pasta diretamente dentro de `Backups`: update.py:286-317).
- `pg_dump` é consistente com os serviços em execução (instantâneo transacional único); **não é preciso parar
  nada**. Ele só segura bloqueios de leitura (bloqueia DDL/migração enquanto roda — não rodar durante uma atualização).
- Imagens DICOM (Orthanc, `ProgramData\VYONIX\PACS`) **não estão no pg_dump**. Opcional: `VyonixPlatform.exe
  pacs-backup` (incremental, verificado por SHA-256, não apaga nada; grava um evento de auditoria — escrita
  não destrutiva). Consistência banco × imagens não é atômica: fazer o dump do banco **e logo depois** o do PACS, sem
  envio de estudos no intervalo (pedir ao coordenador para pausar os envios STOW/C-STORE).

if ((Get-FileHash -Algorithm SHA256 -LiteralPath $dump).Hash.ToLower() -ne $h) { throw 'SHA-256 nao confere' }

Copy-Item (Join-Path $dir 'contagens.txt') (Join-Path $rel ("contagens_$nome.txt"))
Write-Host $res -ForegroundColor Green
}

## 4. Recuperação (somente documentação — NÃO EXECUTAR sem decisão do proprietário)

Árvore de decisão, da menor para a maior intervenção:
1. **Serviço parado / não abre**: `vyonix-deploy.exe verificar` (somente leitura) → atalho "VYONIX - Reparar
   instalacao" ou `vyonix-deploy.exe repair` (diagnóstico; com `--approve-all` reaplica só o que está fora do
   esperado; não toca dados). Mensagem "marcado para exclusão" → reiniciar o Windows (services.py:105-109).
2. **Programa danificado**: executar de novo o instalador **0.3.1** (atualização sobre a instalação; dados em
   ProgramData preservados; o `update` faz backup antes). Instalação inutilizável: `Recuperar_VYONIX.cmd` (padrão =
   só diagnóstico/plano; `-Aplicar` exige `RECUPERAR`, faz backup provado e renomeia — nunca apaga — a pasta do
   programa); reversão com `Reverter_VYONIX.cmd` (não toca o banco). Ref.: Procedimento_Recuperacao_Instalacao_Proprietario.md.
3. **Dados errados/perdidos no banco** (destrutivo: substitui os dados atuais):
   ```powershell
   cd "C:\Program Files\VYONIX\Platform"
   .\vyonix-deploy.exe backups                                   # escolher a pasta (ex.: homologacao-antes-AAAAMMDD-HHMMSS)
   .\vyonix-deploy.exe restore --backup homologacao-antes-AAAAMMDD-HHMMSS --plan-only --out C:\VYONIX_homologacao\plano_restore.json
   # revisar o plano; somente com autorizacao escrita do proprietario:
   .\vyonix-deploy.exe restore --backup homologacao-antes-AAAAMMDD-HHMMSS --approve C:\VYONIX_homologacao\plano_restore.json --confirm backup.restore="RESTAURAR homologacao-antes-AAAAMMDD-HHMMSS"
   ```
   O plano: garante o PostgreSQL ativo, faz `antes-da-restauracao-<run>` do estado atual, para Core e Worker, confere o
   SHA-256, roda `pg_restore --clean --if-exists --single-transaction` (falha = nada alterado), sobe Core (health) e
   Worker (update.py:333-341). Antes, parar manualmente o `VyonixPacsEngine` (`sc.exe stop VyonixPacsEngine`) para que
   nenhum C-STORE entre durante a restauração (o plano oficial não o para — ver achado A06-02) e iniciá-lo no final.
   Depois: health, contagens comparadas com `contagens.txt` do backup, login.
4. **Imagens DICOM perdidas** (pasta PACS danificada, índice no banco íntegro): após o passo 3 (se necessário),
   `VyonixPlatform.exe pacs-verify --src <backup>\PACS` e `VyonixPlatform.exe pacs-restore --src <backup>\PACS`
   (idempotente, pela entrada normal com SHA-256 e auditoria; nunca sobrescreve conteúdo divergente — vyonix/pacs/backup.py:1-14).
5. **Cluster PostgreSQL não sobe (corrompido)**: o `restore` exige o banco ativo. Caminho sem destruir: parar
   serviços, **renomear** (não apagar) `ProgramData\VYONIX\PostgreSQL\17\data`, `vyonix-deploy repair` recria um cluster
   vazio com as mesmas senhas do cofre e então `restore`. **Não testado** neste ciclo nem documentado oficialmente —
   somente com o suporte (a senha do primeiro administrador só é pedida em `install` — cli.py:144; o comportamento do `repair` com cluster vazio não foi verificado).
